# 메인 globe의 80 Ma 맨틀 근사 중첩

상태: `feature/globe-mantle-overlay`에서 구현·검증. 운영 v0.11.0에는 아직 배포하지 않았다.
계획은 [P05](../devlog/20260915_jikhanjung_P05_globe_mantle_approximate_overlay.md),
좌표계 근거는 [정합 검사](mantle-frame-alignment.md)를 따른다.

## 사용과 범위

메인 지구본의 정보 패널에서 **맨틀 근사 중첩**을 켠다. PALEOMAP 계열 표면
(PaleoAtlas 2016 또는 PaleoDEM)을 선택하고, 현재 타임라인이 정확히 80 Ma를 제공할 때
사용할 수 있다. 2002년 지도와 최근 빙기 시간 범위에는 표시하지 않는다.

켜면 재생을 멈추고 80 Ma·구면 투영으로 이동한다. 카메라는 80°E, 10°N을 바라본다.
지표를 절개해 파란 Slabs와 주황 Piles를 보여 주며 각각 켜고 끌 수 있다.
색은 자료 종류이며 온도·유속이 아니다. 절개를 끄면 같은 시점의 온전한 표면과 비교한다.

토글을 끄면 진입 전 시간·투영·카메라·평면 중심 경도·지형 기울기와 자동 회전 선택을
복원한다. 이전 시대 재생은 자동 재개하지 않는다. 다른 연대나 평면 투영을 직접 선택하면
그 선택을 유지하면서 중첩을 해제한다. 같은 80 Ma의 표면 설정은 계속 바꿀 수 있다.

모바일에서는 로딩 완료 후 정보 패널을 잠시 접어 모델이 보이게 한다. 정보 버튼으로
다시 열 수 있으며 저장된 패널 선호는 바꾸지 않는다. 근사 중첩 상태는 정보 패널을
접어도 별도 화면 캡션에 남는다. 현재 A–A′ 팝업은 기존처럼 독립적으로 동작하며
메인 화면과 단면의 자동 공간 연결은 아직 구현하지 않았다.

## 무엇을 근사하는가

[정합 결과](validation/mantle-frame-alignment.json)의 80 Ma 아프리카 기준
`opt1_to_paleomap_matrix`를 사용한다. 구면 표면은 PALEOMAP에 두고, 맨틀에 전 지구
강체 회전 C를 적용한 다음 화면 축 B로 바꾼다: `p_globe = B C p_OPT1`.
반경과 원본 깊이는 변하지 않는다. 메인 지표의 25배 고도 과장을 맨틀에 적용하지 않는다.

인도 경계점 위치 P95가 약 3.066° 남는다. 사용자가 허용한 rough한 공간 비교이며,
히말라야 지표와 바로 아래 구조의 정확한 연결을 보여 주는 것으로 해석하지 않는다.
0.1°의 엄격한 정합 검사를 통과했다고 표시하지 않으며, 원본 정합 기록의 승인 상태도
변경하지 않았다. 사용자 판단에 따른 근사 표시 정책은 별도 설정의 `approximate_overlay`다.

## 절개와 그리기

절개는 목표 PALEOMAP 좌표의 80°E, 10°N 중심, 각반경 45°인 구면 영역이다.
표시 편의를 위한 선택이며 충돌 지역의 지질 경계가 아니다.

- 지표와 선 레이어는 같은 로컬 좌표 내적 기준으로 해당 영역의 fragment를 버린다.
  지표에 합성되는 기후·빙하도 함께 사라진다. 지명도 절개 안에서는 숨긴다.
- 구멍으로 지구 반대편 격자가 비치지 않도록 선의 뒷면을 카메라 위치로 판별한다.
- 맨틀은 구멍 아래 같은 방향의 방사형 영역만 표시해 반대편 맨틀이 겹쳐 보이지 않게 한다.
  원본 메시를 자르거나 새 단면 벽을 만들어 물질 구조처럼 채우지는 않는다.
- 지표 셰이더는 기존 렌더러를 공유한다. 맨틀은 별도 그룹·조명을 사용하고, 모드 해제 시
  geometry/material을 해제한다. 두 번째 WebGL canvas나 렌더 루프를 만들지 않는다.

## 자료 제공과 상태 관리

`annotations/mantle-overlay-80ma.json`에 시점·근사 정책·행렬·절개 범위와 원본/메시
해시를 고정했다. `core.mantle.globe_overlay()`는 현재 카탈로그가 그 원본과 두 레이어의
해시에 일치할 때만 작은 설정과 기존 자산 URL을 메인 페이지에 제공한다.
잘못된 원본, 다른 메시 또는 80 Ma 누락 시 기능을 제공하지 않는다.

기본 페이지에서는 맨틀 바이너리를 요청하지 않는다. 활성화 시 80 Ma의 Slabs/Piles만
기존 `/mantle/assets/` 경로에서 받는다. 전체 51시점이나 판 경계 메시를 미리 받지 않는다.
두 메시의 gzip 합계는 1,898,851 bytes(약 1.90 MB)다. HTML·코드·지표 전송은 별도다.
압축·해시 검증·ETag·immutable 캐시는 기존 서버 경로를 사용한다. 토글·절개 변경으로
추가 요청하지 않는다. 해제 후 재진입은 fetch를 다시 호출하며 브라우저 캐시를 활용할 수
있지만 캐시 적중을 보장하지 않는다.

표면 로딩 완료와 맨틀 메시 검증 후에만 구멍을 연다. 실패 시 지표를 복구하고 재시도
버튼을 제공한다. 해제·연대 변경·투영 변경·WebGL context 상실은 대기 요청을 취소한다.
취소된 응답은 이후 상태를 덮어쓰지 않는다. 모든 좌표/인덱스의 유한성·범위와 바이트
길이를 확인한 뒤 메시를 만든다.

## 검증

```bash
make check
make test
npm test
node --test tests/mantle-overlay.test.mjs
# 기존 파생 자료가 준비된 개발 서버:
VIEWER_URL=http://127.0.0.1:8144/ node tests/mantle-overlay-browser.mjs
VIEWER_URL=http://127.0.0.1:8144/ node tests/globe-browser.mjs
```

서버 테스트는 원본·시점·레이어 해시 제한과 영문 문자열을, 수치 테스트는 감사 행렬과의
일치·축 방향·반경·역변환을 확인한다. 브라우저는 기본 데이터 요청 없음, 80 Ma 두 요청,
절개 및 레이어 토글, 평면 진입·복원, 연대/투영 변경 해제, 실패/재시도와 취소 후 복구,
모바일·영문·PaleoDEM을 확인한다. 기존 전체 globe 회귀 검사도 수행한다.
