# jikhanjung 069 — OPT1·Müller·PALEOMAP 좌표계 정합 검사

날짜: 2026-09-15 · 브랜치: `feature/mantle-frame-alignment` · 상태: 후보 변환 검증 완료, 운영 미적용

[P04](20260915_jikhanjung_P04_globe_mantle_section_integration.md)의 좌표계 선행 검사를
진행했다. 최신 main과 열린 PR·이슈를 확인하고 feature 브랜치를 만들었다.
구현·수식·측정 기준은 [좌표계 문서](../docs/mantle-frame-alignment.md), 행렬과 판별
오차는 [수치 기록](../docs/validation/mantle-frame-alignment.json)에 있다.

## 확인한 것

- 맨틀 원본 xyz에서 메인 globe의 로컬 축으로 바꾸는 식은 `(x,z,−y)`다.
  기존 맨틀의 x축 −90° 회전과 같으며, 화면 축 자체의 임의 경도 보정은 필요 없다.
- 현재 Müller v1.2.4 README에 맨틀 기준틀 재최적화가 명시되어 있다. 같은 계열이라는
  이유만으로 OPT1 시각화 결과와 절대 회전까지 같다고 볼 수 없다.
- 현재 Cratons GPML–VTU의 고유 대응점 15,149개, 8개 판/블록을 확인했다.
  파일마다 연결 배열이 달라 번호 대응을 그대로 사용하면 잘못된 짝이 섞인다.
  모델 회전을 사용하지 않고 궤적 회전을 추정한 뒤, 추정에 쓰지 않은 점과 실제
  과거 VTU 기하를 공간적으로 다시 대응시켜 검증했다.
- 80·60·40·20·0 Ma에서 아프리카 기준 전 지구 회전으로 OPT1과 Müller의 다른 판을
  함께 맞출 수 있다. 필요한 회전은 과거 네 시점에서 0.147–0.283°이고,
  8개 판 자세의 최대 잔차는 0.000004° 미만이다. 이는 기하 일관성의 수치 오차다.
- PALEOMAP은 아프리카를 맞춰도 인도 경계점의 위치 P95가 약 3.1–3.9° 남는다.
  다른 판에서도 서로 다른 잔차가 남아 전 지구 회전만으로 정합할 수 없다.

## 남긴 구현과 검증

- `scripts/frame_alignment.py`: 축·반경·깊이, 강체 회전, 각거리, 단면 법선과 반평면 변환.
- `scripts/audit_frame_alignment.py`: 기존 아카이브·회전 파일 해시 검사, 대응점 재검증,
  연대별 행렬·잔차·미리보기 생성. 대용량 신규 다운로드는 없다.
- `data/derived/frame-alignment/preview.html`: 연대·대상 모델·보정 여부·지역 확대를
  바꾸며 비교하는 로컬 HTML. 원본 자료·큰 미리보기는 Git에 넣지 않고 수치 요약만 기록한다.
- 합성 수치·잘못된 대응·실제 변형 거부 검사 5개 통과. 실제 자료에서 독립 검증점의
  최대 위치 잔차 약 0.00000127°. 비교 HTML의 브라우저 조작과 페이지 오류 없음 확인.
- `make check`, Django 61개 테스트, 기존 JavaScript 회전·투영 검사 통과.

## 다음 적용 방향

다섯 연대의 OPT1↔Müller 후보 행렬을 다음 내부 장면의 기반으로 사용한다. 우선 OPT1
원본 맨틀·단면·동봉 판 경계를 유지하고, 필요하면 Müller 표면을 역변환한다.
단면을 다른 기준틀로 옮길 때는 선과 법선·반평면도 같이 바꾼다.

PALEOMAP/PaleoDEM은 별도 비교 패널을 유지한다. 판별로 맨틀을 따로 회전시켜
지표에 억지로 맞추지 않는다. 전체 해양 판 경계, 실제 래스터, 다른 연대와 연대 사이
보간은 미검증이다. 이번에는 runtime 자료와 운영 배포를 변경하지 않았다.
