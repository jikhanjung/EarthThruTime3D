사용자는 열린 PR을 검토하고 괜찮으면 병합하도록 요청했다. 현재 열린 것은 #56 하나다.

## 1. 제한 거리 탐색에서 도달 가능한 연결을 놓친다

`scripts/present_water.py:141–165`, `lowest_path()`.

탐색 큐에는 이동 횟수가 있지만 `best`와 `before`는 좌표만 키로 사용한다.
높이가 낮은 긴 경로가 셀을 먼저 방문하면, 더 짧지만 약간 높은 경로는 버려진다.
긴 경로의 남은 이동 횟수가 부족하면 제한 안에 존재하는 연결도 `None`이 된다.
하천의 짧은 공백 연결이나 해안까지 연장이 누락되어 다른 유역으로 넘칠 수 있다.

다음 6×8 고도 배열에서 시작 (2,2), 목표 (2,6), limit=4로 재현했다(좌표는 행·열).
직접 동쪽으로 네 번 이동하면 도달하며 최대 고도는 5지만 현재 결과는 `None`이다.

```python
z = np.array([
    [6,3,8,3,6,6,0,6],
    [5,7,2,9,0,6,3,6],
    [1,6,3,5,0,5,4,7],
    [6,7,3,7,5,8,1,2],
    [9,1,9,1,0,3,2,3],
    [8,8,6,4,4,4,3,0],
])
target = np.zeros(z.shape, bool)
target[2,6] = True
assert lowest_path(z, target, (2,2), 4) is None  # 현재 결함
```

수정 방향: 좌표와 이동 횟수를 함께 상태로 두거나, 고도와 이동 횟수에 대한 비지배 상태를
보존한다. 경로 복원도 같은 상태를 따라야 한다. 이 반례를 회귀 검사에 추가한다.

## 2. 호수 안의 섬까지 물로 채운다

`scripts/present_water.py:184–195`, `lakes()`.

Shapefile의 모든 ring을 `fill=1`로 그려 내부 구멍과 외곽을 구별하지 않는다.
외곽과 반대 방향의 내부 ring을 가진 합성 호수에서 섬 중앙의 기대 깊이는 0인데 10 m가 나왔다.
호수 표시뿐 아니라 `closed` 유출 셀 마스크에도 같은 오류가 전파될 수 있다.

128×64 격자, 전체 고도 1 m, Lake_area=1000, Depth_avg=10으로 아래 ring을 사용했다.

```text
외곽: (-90,-45),(-90,45),(90,45),(90,-45),(-90,-45)
내부: (-30,-15),(30,-15),(30,15),(-30,15),(-30,-15)
검사: depth[32,64] == 10.0  # 기대 0
```

수정 방향: 외곽과 내부 ring을 구별해 구멍을 제외한다. 다중 외곽과 섬을 포함한 fixture로
깊이와 폐쇄 호수 마스크를 함께 검사한다.

## 3. 캐시를 고도·원본·처리 규칙에 연결하지 않는다

`scripts/present_water.py:200–218`, `load()`.

캐시는 burn의 shape와 closed 키 존재만 맞으면 즉시 반환한다. `closed`는 입력 고도 z의
0 m 기준에, burn은 z를 사용하는 하구 확장·분수계 판정에 의존하지만 z의 해시가 없다.
원본 manifest나 처리 규칙 버전도 비교하지 않는다. 원본/고도/알고리즘을 바꾸고 다시 실행해도
같은 해상도라면 이전 결과를 재사용한다. 캐시가 없을 때도 SHP 존재만 확인하고 읽는다.

합성 64×128 NPZ를 만든 뒤 z=0과 z=1000으로 각각 load했다. 원본 자료가 없는 상태에서도
동일한 캐시가 반환됐고, 1000 m로 바꾼 고도에도 이전 closed=True가 전부 유지됐다.

수정 방향: 캐시 키에 고도·원본 식별/해시·처리 규칙 버전을 넣고 모든 배열의 형식/크기를
검사한다. 새 캐시는 검증된 입력에서만 만들고, 누락/손상/키 불일치를 명시적으로 처리한다.
