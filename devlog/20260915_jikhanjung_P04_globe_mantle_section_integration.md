# jikhanjung P04 — 메인 globe에 맨틀과 인도–아시아 단면 통합

날짜: 2026-09-15 · 기준 버전: v0.11.0 · 상태: 계획, 구현 미착수

## 목적

메인 지구본에서 시간을 바꾸고 인도–아시아 지역을 선택하면, 그 시점의 지표·맨틀·
A–A′ 단면을 함께 탐색할 수 있게 한다. 현재 별도 페이지와 팝업으로 검증한 기능을
하나의 탐색 흐름으로 연결하는 것이 다음 작업이다. 이번 문서는 계획만 기록하며,
운영 서비스는 [jikhanjung 068](20260915_jikhanjung_068_release_0110.md)의 배포 상태로 둔다.

[P03](20260915_jikhanjung_P03_crustal_deformation_mantle_coupling.md)의 장기 목표인
지각 변형·맨틀 결합을 대체하지 않는다. 이번 단계의 완료는 표시와 탐색의 통합이며,
지각 이동의 원인을 푸는 물리 모사의 완료를 뜻하지 않는다.

## 출발점과 제약

| 항목 | v0.11.0에서 확인한 상태 | 다음 단계에서 필요한 일 |
|---|---|---|
| 메인 globe | PALEOMAP 지표, 판 회전·기후 레이어, 구면 고도 표현 | 시간·장면 상태를 새 레이어와 공유 |
| 맨틀 | `/mantle/`에서 OPT1 추출 표면 51시점, 1000–0 Ma, 20 Ma 간격 | 구면 축·깊이 변환과 기준틀 검증, 선택 시점 로딩 재사용 |
| 지역 단면 | 고정 85°E, 40°S–60°N, 80·60·40·20·0 Ma | 메인 지구본의 단면선 및 시간과 연결 |
| 지역 3D 지표 | 같은 다섯 연대의 PaleoDEM을 평면 지역 격자로 표시 | 검증 후 구면 위치에 표시하거나 메인 지형으로 대체 |
| 지각 시나리오 | 별도 거리 좌표의 단축·면적 보존·등압 평형 가정 | 설명 패널로 유지하고 지형·맨틀의 계산 결과와 구분 |
| 대류 화살표 | 기본 꺼짐인 개념도, 속도장 없음 | 개념도 표기 유지; 실제 맨틀 유속처럼 표시하지 않음 |

현재 지표와 맨틀은 **연대만 대응시키며 기준틀 변환은 검증되지 않았다**.
Three.js 축 방향을 맞추는 작업과 지질학적 복원 기준틀을 맞추는 작업은 별개다.
구현 근거와 원본 출처는 [맨틀 문서](../docs/geodynamics.md),
[단면 문서](../docs/india-asia-section.md), [뷰어 문서](../docs/globe-viewer.md)를 따른다.
이 계획을 위해 새로운 외부 자료를 조사하거나 다운로드하지는 않았다.

## 사용자 흐름

1. 메인 globe에서 ‘지구 내부’ 또는 ‘인도–아시아 단면’을 켠다. 기본 지구본은 기존과
   같이 시작하고, 선택하기 전에는 맨틀 자료를 받지 않는다.
2. 인도–아시아 모드를 선택하면 80 Ma부터 현재까지의 다섯 원본 시점을 제공한다.
   이는 관찰 시작 범위이며 충돌 시작 시기를 80 Ma로 정하는 것이 아니다.
3. 지구본에 A–A′ 선과 끝점, 방향을 표시한다. 단면 패널에는 지표, 맨틀 절단면,
   지각 가정의 출처·연대·배율을 각각 표시한다.
4. 메인 시간 조절기로 모든 뷰를 갱신한다. 내부 모드에서는 맨틀 레이어와 지표
   절개를 켜서 볼 수 있다. 해제하면 이전 표면·시간 범위·카메라 설정을 복원한다.
5. 데스크톱은 지구본 옆 패널, 모바일은 접을 수 있는 패널을 우선한다. 확대 단면은
   기존 팝업을 재사용할 수 있게 하고, 닫기·Escape·포커스 복귀를 유지한다.

## 1단계 — 공유 시간 상태와 레이어 경계

- `static/core/globe.js`의 시간 변경·투영 변경 지점에 연결할 작은 상태 인터페이스를
  정한다. 요청 연대, 레이어별 실제 자료 연대, 자료 모델, 로딩·오류 상태를 분리한다.
- `mantle.js`, `collision.js`, `collision-surface.js`에서 데이터 읽기와 그리기 수명 관리를
  분리한다. 메인과 독립 페이지가 같은 로더·좌표 변환·계산 함수를 사용하게 한다.
- 우선 범위는 80–0 Ma다. 지역 모드에서 다섯 시점으로 스냅하고, 일반 타임라인의
  중간 연대에서는 해당 자료가 없음을 표시한다. 몰래 가까운 시점을 현재 시점으로
  취급하거나 전체 메인 타임라인을 20 Ma 간격으로 바꾸지 않는다.
- 모델마다 연결 구조가 다른 맨틀 메시의 정점 보간은 하지 않는다. 1만 년 눈금이나
  매끄러운 전환은 별도 과제다. 시각적 전환을 추가할 때도 원본 연대와 구분해야 한다.

완료 조건: 시간 상태를 한 번 바꾸면 각 패널의 실제 연대가 일관되게 바뀌고,
빠른 입력·실패·재시도 중 이전 프레임에 새 연대가 붙지 않는다. 기존 시간 범위와
투영 전환이 유지된다. 이 단계에서는 비교 패널 연결까지 진행할 수 있다.

## 2단계 — 좌표계 정합: 구면 중첩의 선행 조건

- OPT1 원본 xyz, 화면용 축 변환, 구면 반지름 1과 깊이 km의 관계를 공통 함수로
  명시한다. 경도 0°·90°·180°, 적도·극, 알려진 깊이의 합성 점으로 축·부호·단위를 검사한다.
- 기존 Müller 2022 판 회전 자료가 OPT1 부속 판 경계와 어떤 복원 기준틀을 공유하는지
  확인한다. 모델 이름이나 동일 논문 출처만으로 일치한다고 가정하지 않는다.
- 다섯 연대에서 OPT1 경계·대륙 내부와 해당 판 회전 결과를 비교한다. PALEOMAP과의
  연결에는 자료별 기준틀, 필요한 연대별 회전, 적용 범위와 남는 오차를 기록한다.
- 표시상 맞아 보이도록 단일 경도 오프셋을 임의로 적용하지 않는다. 복원 자체가
  다른 자료는 하나의 전 지구 회전으로 완전히 정합되지 않을 수 있다.
- 검증 결과에 따라 OPT1과 호환되는 표면·판 레이어로 내부 모드를 구성하거나,
  PALEOMAP과의 비교 패널을 유지한다. 정합 근거가 없으면 물리적으로 이어진
  지표–맨틀 구면 중첩은 보류한다.

완료 조건: 변환식·원본/대상 기준틀·각 연대의 비교 그림과 오차를 검토 가능한 문서로
남긴다. 자료 해상도와 비교 목적에 근거한 허용 오차를 정하고, 통과한 조합만 중첩한다.

## 3단계 — 메인 장면의 맨틀과 절개 표시

- 검증된 변환을 적용한 맨틀 그룹을 메인 Three.js 장면에 추가한다. 섭입 잔재 표면,
  심부 구조 표면, 판 경계를 각각 토글한다. 색은 레이어 구분이며 온도·속도가 아니다.
- 불투명 지표가 내부를 가리므로 지역 절개를 우선 구현한다. 지표 투명도는 보조
  비교 기능으로 검토한다. 절개는 표시 마스크이며 원본 메시를 수정하지 않는다.
- 고도·해양·빙하·경계선·라벨에 절개가 어떻게 적용될지 정한다. 잘린 지표 위에
  선이나 라벨만 남지 않는지, 깊이 순서와 뒷면이 올바른지 확인한다.
- 맨틀 깊이는 실제 반지름 비율을 유지한다. 단면의 높은 수직 과장을 지구 내부
  반지름 전체에 적용하지 않는다. 고도 과장은 기존 메인 지형 설정과 공유한다.
- 평면 투영에서는 내부 입체 표시를 숨기고 이유를 표시한다. 구면으로 돌아오면
  선택 상태를 복원한다. 초기 구현에서 모든 투영의 내부 모사를 시도하지 않는다.

완료 조건: 구면 회전·확대·기울이기와 절개를 함께 사용해도 레이어 위치가 일치한다.
내부 모드 해제 시 클리핑·투명도·카메라와 GPU 자원이 정상적으로 정리된다.

## 4단계 — A–A′ 단면과 지표 연결

- 초기 단면은 기존 85°E 고정 공간 단면을 유지한다. 사용자가 재료를 따라가는
  단면으로 오해하지 않도록 표기한다. 자유 단면·이동 단면은 후속 과제로 둔다.
- 단면 정의에는 기준틀·연대·끝점·방향·누적 거리 km를 포함한다. 기준틀을 변환하면
  맨틀만 옮기지 않고 절단면 정의도 함께 변환해, 지도 선과 실제 절단 위치를 맞춘다.
- 지구본의 선 선택과 패널의 위치 표시를 연결한다. 단면 끝점, 중간점, 거리 방향이
  지구본과 동일한지 검사한다. 기존 평면 지역 지형을 그대로 구면 위에 붙이지 않는다.
- 지표·맨틀·지각 시나리오의 수직 배율은 각각 표시하고 독립 조절한다. 배율 변경이
  원래 고도·깊이·지각 두께 계산값을 바꾸지 않게 한다.
- 지각 가정은 별도 로컬 좌표 패널로 유지한다. 설명 모형의 융기량을 PaleoDEM에
  더하거나 관측된 히말라야 지형인 것처럼 구면에 표시하지 않는다.

완료 조건: 다섯 연대의 단면선·절단 데이터·지표 출처가 서로 추적 가능하고, 좌표가
정합된 조합에서만 공간 연결을 표시한다. 데스크톱·모바일에서 조작과 범례를 읽을 수 있다.

## 전송량과 자원 관리

기존 측정값은 맨틀 현재 시점 세 레이어 gzip 약 2.04 MB, 51시점 전체 약 92.5 MB,
지역 다섯 시점 합계 420,502 bytes다. 정적 파일 등은 별도이며 과금 예측값은 아니다.

- 기존 파일과 해시 기반 URL·gzip·캐시를 재사용한다. 이번 통합에 대용량 온도장이나
  속도장 다운로드를 선행 조건으로 두지 않는다.
- 기본 페이지에서는 새 데이터 요청 0건을 목표로 한다. 선택한 시점만 가져오며,
  기본 자동 재생·전체 시점 사전 로딩은 하지 않는다.
- 메인/패널의 동일 자료 요청을 공유한다. 연속 입력 취소와 요청 지연을 유지하고,
  CPU 배열·GPU geometry 캐시는 상한을 두어 오래된 시점을 해제한다.
- 현행 독립 화면을 기준으로 전송 bytes, 첫 표시 시간, 프레임 시간, GPU 메모리
  증가를 측정한다. 성능 목표 수치는 대상 기기의 기준 측정 후 정한다.

## 검증과 릴리스 순서

1. 공유 상태·좌표 변환의 수치 검사와 원본 뷰 비교를 먼저 수행한다. 반경·깊이,
   경도 경계, 절단 방향, 배율 불변성과 빠른 시간 변경을 검증한다.
2. Django 자료 제공·해시 검증과 기존 `make check`, `make test`를 통과시킨다.
   브라우저 검사에는 기존 globe 회귀, 맨틀/단면 동기화, 요청 중복·취소,
   패널 닫기·재열기, 투영 변경, 모바일·영문·키보드 조작을 포함한다.
3. 좌표 정합 결과와 통합 화면을 검토한 후 기능 PR을 작성한다. 구현은 최신 main을
   확인한 새 feature 브랜치에서 시작하고, 큰 단계는 검증 가능한 PR로 나눈다.
4. 다음 버전 배포 때 데이터 묶음과 이미지 스모크에 통합 경로를 추가한다. 개발
   호스트 빌드, 운영 백업·해시 검증·교체·공개 화면 확인과 롤백 절차를 유지한다.
5. 기존 `/mantle/`, `/collision/`은 회귀 비교와 직접 링크를 위해 유지한다.
   구현 결과·성능 측정·미해결 한계는 별도의 작업 devlog에 기록한다.

최소 완료 범위는 **공유 시간 + 검증된 내부 레이어 + 고정 A–A′ 연결**이다.
기준틀 정합이 해결되지 않으면 완료 범위를 비교 패널 연결까지로 명시하고,
구면 중첩을 완료했다고 기록하지 않는다.

## 이후로 남기는 과제

- Müller 2019 변형 네트워크를 해석한 물질 격자·변형률·지각 두께의 운동학적 복원.
- 지역 자료로 구속한 충돌 시기·단축·침식·융기 시나리오 비교.
- 온도·속도장의 존재와 필요 용량을 확인한 뒤 필요한 지역·깊이만 전처리해 도입.
- 맨틀 경계조건을 주는 물리 모사와, 그 이후의 양방향 지각–맨틀 결합.
- 자유 단면, 이동하는 물질 단면, 더 촘촘한 시간 보간과 1만 년 표시 tick.

각 과제는 P03의 후속 단계로 다루며, 시각화 통합만으로 해결된 것으로 간주하지 않는다.
