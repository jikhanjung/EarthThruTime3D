# PR #48 — 호수 채널 전환의 캐시·자료 형식 보완

- 최신 작성자 head e1fc0d3(웅덩이별 50% 중첩 규칙)을 기준으로 main을 병합했다.
- 하천·저수위·빙기 URL에 format=river-lake-rgb-v1을 붙여 기존 한 채널 PNG 캐시와 분리했다.
- 패커가 2048×1024, 8-bit RGB PNG 헤더를 요구하도록 했다. 기존 L/RGBA·다른 크기·잘못된
  헤더를 거부하는 회귀 검사를 추가했다. 실제 이전 L 필드 거부도 확인했다.
- migrate_river_rgb.py는 일반·저수위만 변환한다. 빨강을 유지하고 G/B=0을 보장하며,
  빙기 필드는 건드리지 않는다. 반복 실행 검사를 포함했다.
- 기존 일반 109장·저수위 31장을 변환하고 140장 모두 이전 원본의 red와 바이트 단위로
  비교해 일치함을 확인했다. 모든 G/B는 0이다. 이전 PNG는 .build/river-before-rgb에 보관했다.
- 빙기 2.5–25 ka 10장을 새 호수 계산으로 다시 생성했다. 50% 중첩 기준은 근사 규칙이며
  검증된 실제 호수 복원이 아니라는 점을 한영 화면 안내·문서·빌더 설명에 맞췄다.
- make check, Django 77개, JS 6개 파일, 하천/패킹/변환 검사 12개 통과.
- 기능 추가 릴리스 버전은 0.15.0으로 맞췄다. 150장 모두 RGB 헤더 검사를 통과했으며 PNG 합계는 61,082,334 bytes다.
- Firefox BiDi: 지구·하천, −60 m의 12.7 ka 보간, 20 ka 빙상/하천, 콘솔·네트워크 오류 없음 확인.
- 추가 브라우저 검사: PNG·셰이더·토글·저수위/시간 창·모바일·한영 안내 모두 통과.
