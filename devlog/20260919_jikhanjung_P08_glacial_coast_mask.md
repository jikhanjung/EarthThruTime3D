# jikhanjung P08 — 시간 창의 해안선을 빌더의 바다 마스크로 (#59 (c) 1단계)

날짜: 2026-09-19 · 기준 버전: v0.19.0 · 이슈: [#59](https://github.com/jikhanjung/EarthThruTime3D/issues/59) · 검토: [jikhanjung 100](20260918_jikhanjung_100_glacial_window_paleomist_review.md) · 상태: 계획

## 목적

시간 창(최근 2.5만 년·13만 년)의 해안선은 셰이더가 **높이 − 해수면**으로 자른다
(`globe.js` `main()`, `abs(seaLevel) > 0` 분기). 연결성을 보지 않으므로 빙하 무게로 눌린
지각을 반영하는 순간 애거시·발트 빙호·그레이트슬레이브 저지·20 ka 남부 북해가 모두
바다가 되고, 같은 곳을 하천 빌더(`build_rivers.py sea_at`)는 호수로 처리해 초록 채널을
그린다. 지형과 하천이 같은 자리를 다르게 말하게 된다.

이 계획은 창의 해안선을 **하천 빌더가 계산한 바다 마스크**로 자르게 한다. 그러면 창의
해안선·호수·하천이 한 계산에서 나오고, 샹플랭해는 바다, 애거시는 호수, 티렐해는 바다가 된다.
지형 색과 3D 기복은 현재 고도 그대로 둔다(2단계, 아래 "나중에").

## 정한 것 (2026-09-19)

- **해안선의 결정자는 빌더다**(검토한 A·B 중 B). 창에서 셰이더는 높이 자르기를 끄고
  마스크의 부호 거리장으로 해안선을 자른다. 둘을 함께 쓰지 않는다(이중 적용 금지).
- **1단계는 마스크만.** 침강 텍스처는 만들지 않는다. 지형 색·기복·3D lift는 지금 그대로.
- 침강은 빌더 규칙대로 **전 지구**에 적용된 결과를 쓴다. 해양 평균을 뺀 뒤 남는 원거리
  효과(±10–20 m)로 빙하에서 먼 해안선도 조금 움직인다. 이동량을 보고하고 문서에 적는다.
- 표본은 **2.5 ka 스텝 32장**, 창 안에서 나이 기준으로 두 장을 섞는다(하천 빙기 필드와
  같은 스텝·같은 `t`).
- 마스크의 의미는 `sea_at` 그대로: 변형된 지표에서 해수면 이하이며 세계 해양과 연결된 곳
  (반자오선 넘어 연결 포함) + 격자 자체가 해수면 이하로 든 곳. 연결되지 않은 침강 분지는
  육지(호수). 카스피해는 격자가 0 m 수면이라 저수위에서 육지(기존 문서의 예외 그대로).
- ≤25 ka의 화면 빙상은 NADI/DATED, 마스크의 얼음은 PaleoMIST다. 둘이 다른 곳에서는
  빙하 가장자리에 바다·호수 조각이 보일 수 있다. 하천이 이미 같은 조건이므로 **받아들이고
  문서화**한다. NADI 기반 재라우팅은 하지 않는다.
- **창 전용.** 전체 시리즈의 해수면 what-if 슬라이더에는 쓰지 않는다(시점이 없다).
- 0 ka 창 프레임은 해수면 0이라 기존 0 m 거리장 경로를 그대로 탄다. 마스크 없음.

## 자료에서 확인한 것 (100)

- 침강 = PaleoMIST `sea_level` − 현재 해양 코사인 가중 평균, 양수가 침강. 20 ka 허드슨만
  +327 m, 보스니아만 +371 m, 네덜란드 −8 m, 적도 태평양 −13 m. 최대 침강 약 650 m.
- `paleo_topography`는 PaleoMIST 자체 해수면이 들어 있어 쓰지 않는다.
- 빌더의 해수면은 페이지 값과 같다(25 ka까지 held, 그 뒤 스택, 반 스텝은 이웃 평균).

## 설계

### 자료 생성 (`scripts/build_rivers.py --ice`)

- `ice_slices`가 각 스텝에서 이미 `land = ~sea_at(surface, level, z)`를 계산한다. 이 `land`를
  `segment_paleoatlas.signed_field`로 부호 거리장으로 만들어
  `paleodem-0000-coast-ice-<years>.png`(L 모드, 한 채널)로 쓴다. 인코딩은 고도 텍스처의
  R 채널과 같다(`FIELD_ZERO`가 해안, 육지 양수).
- 하천 sidecar `paleodem-0000-rivers-ice.json`의 각 스텝에 `coast: true`를 더한다. 별도
  sidecar를 두지 않는다. 마스크가 없는 스텝(이전 묶음)은 `coast`가 없어 페이지가 높이
  자르기로 돌아간다.
- `--ice-to 80` 전체 재생성이 필요하다(스텝당 약 50초). 하천 PNG는 바뀌지 않아야 한다
  (바이트 비교로 확인).
- 크기: 32장 × 약 150–250 KB ≈ 6 MB.

### 서버 (`core/globe.py`)

- `rivers_ice_steps`가 `coast`를 읽어 파일이 있으면 각 스텝에
  `coast_url`(`/globe/coast-ice/<id>/<years>.png`)을 붙인다. 창 프레임만 이 목록을 받으므로
  전체 시리즈에는 노출되지 않는다.
- 새 뷰·경로 `globe-coast-ice`, 없으면 404. 캐시 헤더는 다른 파생 PNG와 같다.

### 페이지 (`static/core/globe.js`)

- `riverChoice`가 창에서 고른 두 스텝과 `t`를 그대로 쓴다. 창 프레임에서 두 스텝 모두
  `coast_url`이 있을 때만 마스크를 켠다(`coastMix` 1). 0 ka 쪽(`base`가 own)은 현재
  고도 텍스처의 R 채널을 그대로 쓴다.
- 새 uniform: `coast0`, `coast1`(sampler), `coastT`, `coastMix`. 셰이더의 창 분기:
  `coastMix > 0.5`이면 `distance = mix(coast0.r, coast1.r, coastT) − 0.5`로 `landness`를
  구하고 높이 자르기를 건너뛴다. `metres`는 그대로 색에 쓰되 마스크가 육지인 곳은
  `max(metres, 0)`으로 잘라 해수면 아래 육지가 바다 색으로 칠해지지 않게 한다.
- 3D lift는 `max(metres, 0)`이라 마스크 육지가 해수면 아래여도 가라앉지 않는다(0 높이).
- `data-coast-ice`에 마스크의 보간 나이(하천의 `data-river-ice`와 같은 값), 마스크가 없으면
  빈 문자열. 캡션·안내: 빙하 안내의 "빙하 무게로 지각이 눌린 효과는 반영하지 않았습니다"를
  "해안선에는 반영하고 지형 색·기복에는 반영하지 않았습니다"로 바꾼다(한영).
- 셰이더 밖 변경 없음: 하천·빙상·호수 경로 그대로.

### 표시 원칙

- 마스크는 발표된 복원(PaleoMIST 침강 + 격자 지형 + 스택 해수면)에서 **계산한** 해안선이다.
  관측 해안선이 아니며 20 km 격자가 실제 문턱을 해상하지 못한다는 하천 문서의 단서를 같이 단다.
- 유사 자료 구간(81–130 ka)은 하천처럼 해수면 기준으로 고른 스텝의 마스크를 쓴다(같은
  해수면이었던 후퇴기의 해안선). 가정 안내에 한 문장 더한다.

## 검사

- `tests/rivers_check.py`: (1) 작은 격자에서 마스크가 `sea_at`과 일치, (2) 연결되지 않은
  침강 분지는 육지, (3) 0 ka 상당(침강 0·해수면 0) 마스크의 거리장이 고도 텍스처 R 채널과
  같은 인코딩(`signed_field` 동일 함수).
- Django: 창 프레임의 스텝에 `coast_url`이 있고 전체 시리즈 프레임에는 없음, 파일 없는
  스텝은 `coast_url` 없음, 경로 404.
- 브라우저(정거원통, 픽셀 표본):
  - 12.5 ka 샹플랭해(45.5 N, 73.5 W) = 바다색, 0 ka = 육지.
  - 12.5 ka 애거시 중심(50 N, 97 W) ≠ 바다색(호수 채널 또는 육지).
  - 12.5 ka 발트(58 N, 20 E) ≠ 바다색(발트 빙호), 11 ka 이후 바다.
  - 8 ka 허드슨만(60 N, 85 W) = 바다(티렐해).
  - 20 ka 도버 해협(51 N, 1.5 E) = 육지, 남부 북해(54 N, 3 E) ≠ 바다색.
  - 콘솔·네트워크 오류 없음. `data-coast-ice`가 하천 나이와 같음.
- 실제 자료: 순다 대륙붕(−117 m, 20 ka)과 베링 육교의 해안선 셀 수를 0.19.0 방식(높이
  자르기)과 비교해 이동량을 기록한다. 25/26 ka와 80/81 ka 경계에서 마스크 면적 변화를 본다.
- `make check`, `make test`, `npm test`, 기존 브라우저 검사 2종.

## 순서

1. 빌더: 마스크 쓰기·sidecar `coast`·검사. `--ice --ice-to 80` 재생성, 하천 PNG 불변 확인.
2. 서버: `coast_url`, 뷰, 경로, Django 검사.
3. 페이지: uniform·셰이더 분기·`data-coast-ice`·안내 문구·번역.
4. 브라우저 픽셀 검사, 실제 자료 이동량 보고, `docs/globe-viewer.md`(Time window·Rivers),
   devlog, PR. 묶음 약 +6 MB.
